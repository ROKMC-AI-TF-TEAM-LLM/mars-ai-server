# 문서 갱신의 실패 복구 (#10)

`POST /documents`와 `scripts/reindex_document.py`의 `ingest_file` 경로에 적용한다.

1. 추출·청킹·임베딩을 기존 데이터 변경 없이 완료한다.
2. 검색과 배타적인 교체 잠금을 잡고 기존 문서의 모든 자식 행(임베딩 포함)과
   부모를 `BM25_INDEX_PATH/ingest-recovery.json`에 저장한다.
3. 부모·자식 청크를 교체하고 BM25를 재빌드한다. 성공 후 저널을 삭제한다.
4. 교체 예외 시 기존 행·부모·BM25를 복원한다. 복구까지 실패하면 저널을 남긴다.

검색끼리는 병렬 실행된다. 교체/복구 중에는 검색이 대기하며, 미완료 저널이
남으면 재시작 후에도 문서 검색·목록·추가 적재/삭제가 거부된다.
`GET /health?deep=true`는 이 상태를 degraded로 표시한다. 잡담 등 저장소를
사용하지 않는 기능은 영향을 받지 않는다.

## 운영 복구

API와 모든 적재·마이그레이션 프로세스를 중지한다. 장애 원인(디스크 용량,
Milvus 연결 등)을 해결한 뒤 **동일한 저장소 설정**으로 실행한다.

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe scripts/recover_ingest.py
```

Linux에서는 앱 가상환경에서 `PYTHONPATH=src python scripts/recover_ingest.py`.
복구는 재임베딩 없이 저널에 보관된 기존 행으로 되돌린다. 성공 시 저널을
삭제하고, 실패 시 보존하므로 원인을 해결한 뒤 재실행할 수 있다.
성공 후 API를 다시 시작하고 실패한 업로드는 미들웨어 원본으로 다시 제출한다.
저널을 수동 삭제해 차단을 해제하지 않는다.

## 범위와 비용

- 저널에는 기존 문서 내용과 임베딩이 포함된다. DB와 같은 보호·보관 정책을 적용한다.
- 메모리·디스크에 해당 문서의 복구 사본 공간이 필요하다. 사본 준비 실패는
  기존 데이터를 변경하지 않는다. 저장소 전체 손상·저널 유실·전원 장애에 대한
  백업 대체 수단은 아니다.
- 잠금은 프로세스 내부용이다. API는 단일 워커이며 별도 적재/복구 스크립트를
  실행할 때는 API 및 다른 쓰기 프로세스를 중지한다.
- 동일 문서의 접수 순서 FIFO는 보장하지 않는다. 이전 작업 종료 후 다음 버전을 보낸다.
- 작업별 업로드 파일은 성공·실패 후에도 자동 삭제하지 않는다. TTL 정리는
  미들웨어 원본 DB 저장의 실동작 확인 후 도입한다 (`roadmap.md` 참조).
  수동 정리 시에는 작업 프로세스를 중지하고 미들웨어의 원본 보관을 확인한다.
- 직접 `indexer_graph.graph`를 호출하는 초기 일괄 적재와 문서 삭제 자체의 실패 복구는
  이번 갱신 저널의 대상이 아니다. 검색과 교체의 동기화 및 미완료 저널 차단은 적용한다.

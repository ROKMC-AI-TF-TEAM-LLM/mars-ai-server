# middleware_migration.md — 미들웨어 연동 변경 안내

프로젝트 단위 RAG와 "근거 없는 답변 경고"가 추가됐다. 대부분 하위 호환이지만
**두 가지는 미들웨어가 대응하지 않으면 문제가 생긴다.**

- 기존 연동은 그대로 동작한다 (필드 추가 전용, 제거·변경 없음)
- 전체 스키마는 Swagger UI(`GET /docs`)가 최신이다. 사양 원문은 `docs/interfaces.md`

---

## 한눈에 보기

| 변경 | 대상 | 대응 | 안 하면 |
|---|---|---|---|
| **project_id 멤버십 검증** | `POST /query` | 🔴 **필수** | 남의 프로젝트 문서가 읽힌다 |
| **notice 이벤트 처리** | SSE | 🔴 **필수** | AI가 지어낸 규정이 일반 답변처럼 보인다 |
| 프로젝트 지정 질의 | `POST /query` | 기능 도입 시 | 전사 문서만 검색 (현행과 동일) |
| 프로젝트 문서 업로드 | `POST /documents` | 기능 도입 시 | 전사 공용으로 적재됨 |
| 프로젝트 삭제 | `DELETE /projects/{id}` | 기능 도입 시 | 문서를 하나씩 지워야 함 |
| 문서 목록 프로젝트 필터 | `GET /documents` | 기능 도입 시 | — |
| `status`에 `thought`·`step` 필드 | SSE | 참고 | — |
| 이벤트 순서에 `notice` 삽입 | SSE | 참고 | 순서 가정 코드가 있으면 점검 |

## 🔴 필수 ① — project_id 멤버십은 미들웨어가 검증해야 한다

MARS는 요청에 실린 `project_id`를 **그대로 신뢰한다.** 기존 `user_department`와
같은 신뢰 모델이다.

즉 사용자가 임의의 `project_id`를 담아 보내면 **자신이 속하지 않은 프로젝트의
문서를 읽을 수 있다.** MARS에는 프로젝트·사용자 매핑 정보가 없어 이 검증을 할 수 없다.

> **요청을 MARS로 넘기기 전에 "이 사용자가 이 프로젝트의 구성원인가"를
> 미들웨어에서 확인하고, 아니면 값을 비우거나 요청을 거부할 것.**

형식이 잘못된 `project_id`는 MARS가 전사 검색으로 떨어뜨린다(범위가 좁아지는 방향).
하지만 **형식이 올바른 남의 프로젝트 ID는 걸러지지 않는다.**
형식 검증은 권한 검증이 아니다.

---

## 🔴 필수 ② — notice 이벤트 (근거 없는 답변 경고)

문서에서 근거를 찾지 못하면 MARS가 정형 사과문 대신 **AI 일반 지식으로 답변**하고,
그 사실을 `notice` 이벤트로 알린다. 경고는 답변 텍스트에 섞여 있지 않으므로
**이 이벤트를 표시하지 않으면 경고가 통째로 사라진다.**

```
data: {"type":"notice","level":"warning","code":"ungrounded_knowledge",
       "message":"이 답변은 내부 문서에서 근거를 찾지 못해 AI의 일반 지식으로 작성한 것입니다. 실제 규정과 다를 수 있으니 반드시 관련 부서나 원문 규정으로 확인하시기 바랍니다."}
```

| 필드 | 용도 |
|---|---|
| `code` | 표시 방식을 고르는 기준. **문구를 파싱하지 말 것** (현재 값: `ungrounded_knowledge`) |
| `message` | 완성된 문구. `code`를 모르면 이것만 띄우면 된다 |
| `level` | `warning` |

- 이 답변은 **`sources`가 빈 배열**이다 → 출처 없음을 오류로 표시하지 말 것 (notice가 이유를 설명한다)
- 군 규정에 대해 **검증되지 않은 내용**이 나가는 경로다. 일반 답변과 시각적으로
  구분되게 표시할 것 (경고 배너 등)

**파서 점검**: 모르는 `type`을 만났을 때 예외를 던지거나 스트림을 끊지 않는지 확인.
무시하도록 구현돼 있어야 한다.

> 프론트 대응 전이면 서버 설정 `KNOWLEDGE_FALLBACK_ENABLED=false`로 이 경로를
> 꺼둘 수 있다. 끄면 기존과 동일하게 정형 안내문이 나간다.

---

## 이벤트 순서

```
status*  →  text*  →  file*  →  notice?  →  sources  →  done
                               ^^^^^^^ 신규 (0~1회)
```

`sources`가 `done` 직전 마지막이라는 규칙은 그대로다.
**"file 다음은 sources"로 가정한 코드가 있으면 점검이 필요하다.**

## 프로젝트 기능 연동

### 질의 — `POST /query`

```json
{
  "question": "야간비행 훈련 기준이 어떻게 되나요?",
  "user_department": "AF_TEAM",
  "project_id": "proj-7f3a"
}
```

- **값이 있으면** — 전사 문서 **+** 그 프로젝트 문서를 검색
- **비우면** — 전사 문서만. 프로젝트 문서는 어떤 경우에도 노출되지 않는다
- 전사 문서의 부서 ACL은 프로젝트 안에서도 그대로 적용된다

### 업로드 — `POST /documents?name=…&domain=…&project_id=proj-7f3a`

지정하면 그 프로젝트 채팅에서만 검색되는 문서로 적재된다. 비우면 전사 공용.

> ⚠️ **질의와 달리 엄격하다** — 형식이 잘못되면 `400`으로 거부한다.
> 조용히 빈 값으로 처리하면 *프로젝트 전용 문서가 전사 공용으로 영구히 남기* 때문이다.
> `400` 응답을 사용자에게 그대로 전달할 것.

### 삭제 — `DELETE /projects/{project_id}`

```json
{
  "project_id": "proj-7f3a",
  "documents": ["부대지침.md", "야간비행.md"],
  "deleted_chunks": 24,
  "deleted_parents": 6
}
```

- **전사 공용 문서는 지우지 않는다.** 빈 값·형식 위반은 `400`
- **동기 처리**다 — 색인 재빌드 때문에 수 초~수십 초 걸릴 수 있다. 타임아웃을 넉넉히 잡을 것
- `404` 해당 프로젝트에 문서 없음 / `409` 다른 적재·삭제 진행 중

### 목록 — `GET /documents?project_id=proj-7f3a`

- 값을 주면 그 프로젝트 문서만, `""`를 주면 전사 공용만, 생략하면 전부
- 응답 항목에 `project_id` 필드가 추가됐다 (기존 필드는 그대로)

> ⚠️ 이 엔드포인트는 **관리용**이라 부서 ACL을 적용하지 않는다.
> 일반 사용자에게 그대로 노출하지 말 것.

## project_id 형식 규칙

| 항목 | 규칙 |
|---|---|
| 허용 문자 | 영문·숫자·밑줄(`_`)·하이픈(`-`) |
| 길이 | 최대 64자 |
| 질의 시 위반 | 전사 검색으로 처리 (오류 없음) |
| 적재·삭제 시 위반 | `400` |

한글·공백·따옴표는 쓸 수 없다. UUID나 `proj-7f3a` 형태를 권장한다.

## 하위 호환 변경 — 대응 불필요

### `status` 이벤트의 `thought`·`step`

검색·도구 실행을 판단한 직후의 `status`에 **선택 필드**가 실린다.

```
data: {"type":"status","stage":"retrieve","message":"군 내부 문서를 검색하는 중...",
       "thought":"휴가 일수는 확인했지만 신청 절차가 안 나와 다시 찾는다","step":2}
```

- 무시해도 동작에 지장이 없다. 서버 설정 `STREAM_THOUGHTS=false`로 끌 수 있다
- 진행 상황을 사용자에게 보여주고 싶다면 활용 가능. 다만 **검증을 거치지 않은 문장**이므로
  답변 본문과 같은 비중으로 표시하지 말 것
